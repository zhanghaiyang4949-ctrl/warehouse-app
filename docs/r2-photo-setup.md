# R2照片存储开通与切换（2026-11-19）

本次只接入照片；库存、离线合并、GitHub备份和人员审核保留。暂不迁移数据库，不自动删除旧照片。

## 1. 在你的Cloudflare账号中开通

1. 打开Cloudflare控制台，进入“存储与数据库 → R2对象存储”。
2. 完成R2开通流程。它有免费额度，但属于按量计费服务，超额可能扣费。
3. 创建存储桶，例如`warehouse-photos`，选择Standard标准存储。不要选Infrequent Access；免费额度不适用于后者。
4. 保持私有：不要启用r2.dev公开访问，不绑定公开自定义域名。
5. 在账号账单中设置费用提醒。提醒不是硬性消费上限。

## 2. 私有桶CORS

将同目录`r2-cors.json`内容复制到该桶的CORS设置。正式管理端的Origin是`https://zhanghaiyang4949-ctrl.github.io`，不包含路径。不要用`*`。

## 3. 创建仅限此桶的访问密钥

在R2的API令牌管理中创建Object Read & Write权限，只允许访问上面创建的桶。接入需要Account ID、Bucket name、Access Key ID和Secret Access Key。Secret只显示一次，保存在你自己的密码管理器中。

不要把Secret发到聊天、截图、网页源代码、GitHub仓库或库存备份里。

## 4. 服务端配置（腾讯云现有审核函数）

本次复用`warehouseQueryV1`作可信签名服务，继续用现有管理密钥验证管理端，查询端继续验证已批准设备。无需给浏览器R2长期密钥，也不要求另外开通Cloudflare Workers付费计划。

在该函数环境变量中新增：

| 环境变量 | 内容 |
|---|---|
| R2_ACCOUNT_ID | Cloudflare Account ID |
| R2_BUCKET | 私有桶名称，例如warehouse-photos |
| R2_ACCESS_KEY_ID | R2的Access Key ID |
| R2_SECRET_ACCESS_KEY | R2的Secret Access Key |

原QUERY_*变量不要删除或替换。没有这些R2变量时旧GitHub照片功能保持可用，不能将R2状态显示为已连接。

## 5. 切换前必须验证

- 部署新审核函数，确认旧登录、审核、GitHub图片和查询功能正常。
- 管理端连接原审核服务，在数据安全的照片存储区域检查R2配置，再显式选择新照片使用R2。
- 真实上传一张测试照片和缩略图，服务端校验JPEG和文件哈希；返回成功后才允许确认库存备份。
- 用已审核查询设备查看该照片；未审核设备不能读取，直接打开桶也不公开。
- 中途暂停/断网后重试，核对不重复写入、不把未上传的照片标成成功。
- 在真实仓库网络测试手机上传和浏览速度，不能用本机模拟结果保证速度。

## 6. 现有照片与回退

旧GitHub图片引用保持不变，新R2图片记录provider和桶及对象路径，库存备份只记录位置和校验信息，不包含长期密钥或临时签名。

切回GitHub仅影响以后创建的新照片；已经生成的R2待上传照片仍需原桶完成，不会偷偷转存到GitHub。删除照片需明确确认，不在本次自动清理。
